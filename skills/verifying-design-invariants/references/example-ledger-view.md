# 实例：`room.log` 从 state.json 改成 ledger 派生视图

这是我们那条上游补丁的完整映射，用来演示五站怎么落在一个真实补丁上。**它同时是反面教材**：补丁本身只有几十行，但四条性质分属四个站，少一站就有一条性质没人守。

## 背景一句话

`room.log` 原来是 state.json 里的一段（真相的第二个副本），改成从 append-only ledger 按需现算的视图。要守的是「视图永远等于书里最后 60 条」这一类性质——**不是**「代码跑起来不报错」。

## S0：四条性质（各一个 owner）

| 编号 | 性质（一句话） | 坏了多贵 | 测试为什么摸不到 |
|---|---|---|---|
| P1 | `seq` 不双用：一次写入失败后重启，不会用同一个序号再写一次 | 书被两行占同一个号，后续读取顺序错乱，要人工修 | 要「写 state 失败 → 重启 → 再 say()」这个顺序才触发 |
| P2 | importer 不得覆写已存在的书 | 用户的书被静默冲掉，不可恢复 | 正常导入路径不覆写，只有重名且判据写错时才发生 |
| P3 | `viewOf(room)` 恒等于书里最后 60 条 memberLine | 界面显示错行，外部可见 | 需要特定追加/截断交错才露出来 |
| P4 | 启动自检 + append 后不变量 | 起来就是坏状态，且没人知道 | 只有真实日志喂进去才判得出 |

## S1：建模与破坏变体

| 性质 | 站 | 出口证据 |
|---|---|---|
| P1 | S1 + S2 | TLC 反例 → 真实调用重放：写 state 失败后重启再 `say()` |
| P2 | S1 | 破坏变体：把判据改回 `text === undefined`，必须报红 |
| P3 | S2 + S3 | fast-check `commands` 缩出最小命令序列 |
| P4 | S4 | 用 ledger 自己的日志跑一遍：能报出「日志不足以判定」算 **S4 工具跑通**，但这条性质的状态记「未判定」——补细日志后重跑才算数 |

**P2 这条要特别记**：它的价值不在模型，在**破坏变体**——把判据改回旧写法必须报红，否则「importer 不覆写」这句话没有任何检查在守。

## S2/S3：桥接与守门

- P3 的回放要能指出：反例里「追加 → 截断窗口 → 重启重建」三步，各自对应代码里哪一行
- 复现不出就**先疑模型**：模型里 view 是个变量，代码里 view 是每次现算的函数——这是最容易出现的「模型与代码不是一件事」

## S4：日志对规格

两件必须写进报告的事：

1. **日志够细吗**——不够细时 trace validation 会假通过（极端情形只记录执行长度也能「通过」）
2. 失败时**在哪一步**对不上——它给不出单条反例，写「反例见附件」等于没写

## 一条已经踩过的坑（跨站）

**协议版本错位**：0.3.1 遇到没有 `room.log` 的环境直接 `TypeError`。这不是 S1–S5 任何一站能抓的，它属于**schema 版本号**：模型假设「一定有 room.log」，而代码要能在没有它的旧数据上起来。⟹ 顺手加一件：版本号写进数据文件头，读的时候先判版本再判内容。
