# 试点：一次真实的多主体验收（2026-11-22，DS-Bot 上游贡献）

这不是示例，是一次真实跑的记录：四个人（模型 / 测试 / 收口 / 交叉验收）按五站签一个真实补丁的 7 条性质。**每一条摩擦都变成了技能里的结构**——这份文件就是那些改动的出处。

> **术语变动**：S5「一条命令能重跑」的判据，试点时是**四项**，现在是**六条**（⑤「证据命令落成仓库脚本」、⑥「观察值不算证据」是后来加的）。下面表格里出现的「S5 四项」「可重跑四项」是当时的原文，不是另一套判据。

## 试点怎么摆的

| 角色 | 管哪站 | 签什么 |
|---|---|---|
| 架构 | S1 | 破坏变体、退出码、bounds、数据形状假设 |
| 测试 | S2 / S3 | 反例逐步映射、三条守门门、头注释四段 |
| 贡献 | S4 / S5 | 真实日志三种判定、一条命令重跑 |
| 侦察 | 交叉验收（只读） | 复跑机器输出、对表、只报矛盾 |

结果：7 条性质里 1 条 `守住`（单写者，L3）、6 条 `未判定`（日志粒度不足，最高 L2）。这个分布不是失败——它说明**六条性质没有生产日志能证，靠测试守住**。

## 第二轮新增的发现（v2 试点）

- **「要跑两次」可以被消灭，不必被记录。** `run-s4.sh` 改完后全新输出目录首跑就 `exit 0`（脚本自建基线，15 秒后自动取第二张快照）。原文档「第一次 2、第二次 0」已经从事实变成历史。
- **观察值不能挂在「守住」下面。** P1 的 `守住（单写者）` 最终只挂三样：S4 `exit 0`、`FAIL=0`、负对照 `exit 1`。步数从「证据」降级成「带时间戳的观察」（1,718 → 1,768 → 1,774），因为日志在长，它自己会变。
- **证据命令只活在群聊里，等于没有。** 检查器最初只有一条贴在图里的命令，别人照文档验会卡在没说出口的「先造临时根再软链两边」；落成 `check-register.sh`（自建临时根、`trap` 清理、退出码透传、参数错误给 2）之后才算闭环。
- **检查器的告警要看表的版本。** 侦察一度以为「缺三列」是检查器误报，实际是那一刻表还没升到 v2；同一条告警在不同 mtime 的表上含义不同，核对时要连 mtime 一起看。

## 第三轮：把发现做成检查器判据（2026-11-22 23:1x）

- **输出要能归因**：JSON 里加 `mtime` 与 `columns`——试点里侦察一度把「缺三列」当成检查器误报，实际是那一刻的表还没升到 v2。告警离开「表的版本」就无法解释。
- **判据不能被绕开**：有人把 `ds-bot/src/host/ledger.js:133` 改成 `ledger.js:133` 来消掉路径告警，证据反而不可核。现在对「带行号但无目录前缀的代码文件名」单独报警，且只在这一行确实没有全路径时才报（避免误伤 `groups.js:442` 这类）。
- **等级不能空挂**：写 `L3` 却拿不出 S4 的 `PASS` → ERROR（L3 的定义就是 L2 + 真实日志）。
- **会漂的数字要被点名**：`守住` 行里出现「步/行数/条数」且没有「观察/快照/非不变量」标记 → WARN。
- **守卫也要一手证据**：`check-register.sh` 的两条保护性检查路径（无参数、错 checkout）在下一轮由本人复跑确认 `exit 2` 且无临时目录残留，此前只有 QA 与侦察的二手记录。

## 第四轮：检查器自己空转（2026-11-22 23:4x）

- **输入集为空的检查必然通过。** 我用一次性命令核交叉引用，判据写的是 markdown 链接 `[文字](路径)`；这个技能里那种链接 **0 条**，于是「断链 0、退出 0」看起来通过了，其实一次都没检查。同一类病当天第三次出现（前两次：`未判定` 的理由判据永远匹配到「未」字；脚本把 `DSH_HOME` 撞名报成 `UNDECIDED`）。
- **结构**：`scripts/check-paths.mjs` 只说三件事——技能自有目录下的反引号路径是否解析得到、references 与 templates 下的每份文档是否都有人引用、候选数是多少。**候选数为 0 → exit 2 `UNVERIFIED`**，与 exit 0 分开，不许并进「通过」。
- **双向实测**（2026-11-22 23:5x 快照；候选数随正文增长，不是不变量）：真目录 exit 0；删掉 `references/gates.md` → 1 并给出 `referencedIn`；在 references 下加一份没人引用的孤儿文档 → 1；只放一份不含技能内引用的 md → 2。
- `check-register.mjs` 早就有 `rows` 计数与「零数据行 → ERROR」，缺的是**路径这一侧**；现在两侧都先报输入集再报结论。

## 第五轮：本机信息不是一个 grep（2026-11-22 23:5x）

- **症状**：把家目录绝对路径（`/Users/<用户名>/tools/...`）改成 `$HOME/tools/...`、把技能自身安装路径改成 `<技能目录>` 之后，我给自己定的验收硬门是「`grep -rn '/Users/'` 结果为 0」。用户一句话就把这道门拆了：文档里还剩 `/usr/local/bin`、`~/.dsh`、`~/SourceCode`——同一种病，换了个形状。**按字符串判的门，只抓得住它自己写下的那个字符串。**
- **改法**：先把「本机信息」分成四类，再按类判——
  ① **身份路径**（`/Users/<名字>`、`/home/<名字>`、`C:\Users\<名字>`）：任何位置都是 ERROR，连「本机快照」段落里也不许出现别人的用户名；
  ② **家目录假设**（`~/...`、`$HOME/...`）出现在**可执行命令**里：ERROR；
  ③ **宿主绝对路径**（`/usr/...`、`/opt/...`、`/Library/...`）出现在可执行命令里：ERROR；
  ④ **散文里的本机事实**：必须落在标注了「本机 / 快照 / 已实测」的段落，或行内写「（本机…）」，否则 WARN（`--strict` 算失败）。
  唯一豁免是 `${VAR:-默认值}`：默认值本来就是「本机取值、可被覆盖」，那是这台机器的合法位置；把它写进命令正文（而不是变量默认值）才是把机器带进文档。
- **结构**：`scripts/check-portability.mjs`，exit 0/1/2（2 = 没扫到任何文档 = 未校验），输出先报 `docs` / `commandLines` / `proseLines` 再报结论。
- **六向实测**：身份路径 → 1；命令里的 `~/tools` → 1；命令里的 `/opt/...` → 1；未标记段落里的 `~/SourceCode` → 默认 0（WARN）、`--strict` → 1；`${TLA2TOOLS:-/opt/...}` → 0（豁免有效）；空目录 → 2。真目录：11 份文档、93 行命令、649 行散文，0 error / 0 warning。
- **顺手改掉的**：`PATH=/usr/local/bin:$PATH` 全部换成 `PATH=${NODE_BIN:-/usr/local/bin}:$PATH`（9 处）；`~/.dsh` 标注「（本机取值）」。改完在干净 shell 里照文档重跑：三个检查器 0、例子仍是 0/1、0/13、0/1/1/2。

## 第六轮：登记表自己过期（2026-11-26 01:1x）

- **症状**：一个自建的 x402 付费服务的 `invariants/property-register.md` 表头写着「代码基线 `2b64dda`」，但 P1 修完之后模型已在 `60f5cc1` 被改写；同步提交落后三个提交。任何人从 `2b64dda` 起 diff，都会把 `probe_body` 这类与性质无关的改动算成「覆盖代码有变」，而真正该看的修复又被淹没在里面。**这类过期不会让任何东西变红——它让「通过」建立在已经不存在的代码上。**
- **为什么之前的核对没抓到**：原来的两道门只问「表能不能读」与「证据指不指得到东西」，从来不问「这条守住描述的是不是现在的代码」。sync commit 列是自由文本，写什么都过。
- **改法**：`check-register.mjs` 加第三件事——拿「覆盖的文件/函数」与 sync commit 对 git 核一遍；覆盖文件在 sync commit 之后被改过（**含未提交**）报 ERROR；不是 git 工作区时输出 `git_check.checked=0` 并写明未核，**零样本不算通过**；「覆盖同 P1」这类引用沿链解析，不逼人把文件清单抄两遍。配套新增登记表列「承诺变更证据」（性质有意改写时必须指得到 commit 或文件），以及 `references/stations.md` 的「漂移后的维护」四类结论与四类归因。
- **实测**（真数据，不是造的）：改基线前 `verdict FAIL`，P1/P3 各报「覆盖文件在 sync commit（2b64dda）之后有改动 -> sources/index.ts, sources/store.ts」；把基线前移到 `60f5cc1` 后 `git checked 3 / verdict OK`。破坏变体：往 `sources/index.ts` 追加一行注释（不提交）→ **rc=1**，P1 与 P2（沿「同 P1」）同时报「覆盖文件有未提交改动」；`git checkout --` 复原后 **rc=0**。检查器自身的 7 个用例 `node --test scripts/check-register.test.mjs` 全绿。

## 一次就够了吗

不够。这次是**第一次用**，摩擦里有 4 条是在「修上一轮」时新产生的（把状态改单值时漏了备注、改脚本时引入 env 撞名）。所以试点至少跑两轮：第一轮暴露，第二轮验证「改完的结构真的减少了人工裁决」。

第二轮的判据不是「有没有新问题」，而是：**同样这几个人，能不能不再靠 Chief 逐行裁决就交上来。**

照 `templates/verification-record.md` 的签名表分工，把这个文件当检查表用：每条摩擦问一句「这次会不会再发生」，会就去看对应的结构在不在。
