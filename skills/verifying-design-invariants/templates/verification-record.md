# 验证记录（多主体分工时的收敛格式）

性质登记表管「每条性质现在什么状态」；这份记录管「谁签的、签在什么证据上、跑一次要几步」。试点里四个人各写各的，最后拼成这一份。

## 0 头

- 对象：`<branch>` @ `<sha>`（基线 `<dev sha>`）
- 范围：这次验的是哪些性质、哪些层（L1 模型 / L2 回放+守门 / L3 真实日志）
- 签名表：

| 站 | 签的人 | 签的是什么 | 日期 |
|---|---|---|---|
| S1 建模 | | 破坏变体 + 退出码 + bounds | |
| S2 桥接 | | 反例逐步映射 + 重放 exit | |
| S3 守门 | | 三条门逐条 | |
| S4 日志 | | 三种判定与「缺什么」 | |
| S5 收口 | | 一条命令 + 跑几次 | |
| 整合 | 一人 | 合并、对表、跑机器核对 | |

**一个文件只有一个 owner。** 别人只往自己的分区文件写，整合由签名表里那一人做；**改既有文件前先读**。

## A S1 建模（签者：）

每条性质一行：性质原文 / 破坏变体文件 / 报红输出的关键行 / 退出码 / `-workers`。

**图确认**（没有这一行就等于没做「先画图让人确认」）：图文件 / 确认人 / 日期 / 确认的是哪一版（模型在此之前还是之后）。图与模型必须同源：状态名说的是「此刻源可不可见」，不能按「落盘了几个文件」命名——两份变体共用一套状态名时，这类错会静默留下。

> 状态数必须同 `-workers` 一起写。多 worker 下状态数不可复现（同一份模型三跑能出 78/53、90/64、104/64），只有退出码、不变量名、反例序列能承诺复现。

## B S2 桥接 + S3 守门（签者：）

- S2：每条性质给「TLC 反例第几步 → 真实代码哪一行 → 重放命令 → exit」。复现不出先疑模型。
- S3 三条门：①红是预期理由（贴报错原文）②变绿 ③把被测单元换成**失效实现**后**仍失败**——函数用 `return undefined`，生成器输出空文件，接线不注册，词典删一条。判据是「失效了就必红」，不是必须写成某一行代码。
- ③ 首次没过要照实写「首次未过、已修测试」，不许只写最终绿——那条记录本身是证据。

## C S4 真实日志（签者：）

- 三种判定的统计：PASS / FAIL / UNDECIDED 各几条（`UNDECIDED` 不是通过）。
- 逐条写「日志缺什么字段」，不许拿「没签」「没跑」当理由。
- 负对照：故意删一行/改一行，必须 FAIL 并指到步号——证明检查器有分辨力。

## D S5 收口（签者：）

三句话 + 可重跑六项：

1. 这条性质是什么（人话）
2. 从零到通过的一条命令（干净 shell、无额外环境变量、真实退出码、**要跑几次**）
3. 覆盖到哪个 commit，哪里没覆盖

## E 不覆盖（范围声明）

逐条列：模型不管的、测试不管的、日志证不了的，各自归谁。**留空看起来像漏做，写「不覆盖」看起来像诚实。**

## F 机器核对

```sh
node <skill>/scripts/check-register.mjs <property-register.md> --root <仓库根>
# exit 0 = 表读得进来，且证据都指得到东西；1 = 有 ERROR 或硬告警（状态多值 / 表格中断 / 等级词汇不对 /
#          编号重复 / 守住没 0 或 PASS / 守住无破坏变体 / 守住 commit 是 pending / L3 无 S4 PASS /
#          未判定没理由 / 引用的文件不存在 / 代码文件名无目录前缀）
# 它不执行命令：「退出码」列是自述。--strict 另把风格类 WARN 也算失败
```

把这次输出原样贴进来。**人眼核对不算核对**——试点里正是靠这一步才发现状态列塞了整句、备注与表内互相打架。
