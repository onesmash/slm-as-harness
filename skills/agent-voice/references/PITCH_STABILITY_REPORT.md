# agent-voice 音调稳定性：诊断与修复报告

> **读者**：本 skill 的维护者与后续接手的 agent。
> **目标**：不必重跑实验就能判断——「音调忽高忽低」到底是什么、哪条修复可信、哪条已被证伪、如何验收。
> **自包含说明**：本报告不依赖任何外部运行产物。所有数字都在文中给出**测量口径与样本量**；
> 正文引用的是 skill 仓库内的稳定锚点（文件:行、函数名），不是一次性研究目录。
> **状态**：正文有实测支撑；但**未跑完对外发布门禁**（CoVe / E-E-A-T / 引用核验），见 §8。

---

## 1. 结论摘要

「音调忽高忽低」**不是参数没调对，而是三件事叠加**：

1. **逐句独立随机实现**——`sample_mode="fixed"` 实为 ONNX **图内随机采样**，宿主 RNG 跨句单调推进且从不按句重播种；
   而 KV/prefill/重复历史每句都重置，**唯一跨句累积的量就是随机性**（§3.1）。
2. **结构性拼接缺陷**——文本切分器会在恰好吃满 token 预算时把句末标点切成 1–2 token 的**孤儿块**，
   该块有 28.6% 概率撞满解码帧上限，生成 30.0 秒的「近静音夹间歇爆发」断续死气（§3.2）。
3. **增益链自噬**——0.2 秒逐块峰值归一化让 BlackHole 的投递天花板恒为 `0.95·a`（`a` 是设备衰减，**与增益 G 无关**），
   既压掉约 5.2 dB 块动态，又让启动校准的补偿被自己吃掉（§3.3）。

**已实施三条修复**（§4）：切分层移除标点-only 块、每单元常量增益、文本派生稳定种子。
（曾实施第 4 条「跨句前缀 window ≤2 句」，但在 K=16 句 × 3 seed 的事前登记配对测试中**主判据未复现**，
已回滚——见 §4 与 §8。）
**最关键的判据警告**：**不要**用「句间 F0 SD」验收——合成侧跨句离散（1.54–1.85 半音）已经**小于自然人声**（2.68 半音），
该口径判不出用户抱怨的抖动；改用**配对 σ_render 相对门禁**（§6）。

## 2. 现象归属：三条假设的裁决

| 假设 | 裁决 | 实测依据（口径见括注） |
|---|---|---|
| ① 合成侧 F0/韵律不稳 | **成立** | 同一文本、同一进程、同一参考连续合成 4 次（n=4）：F0 中位跨 **4.10 半音**、音频时长差 16.7%、帧 RMS 差 31%。同句只改 seed 的纯解码抖动：8 字句 2.95 半音、24 字句 0.69 半音（各 n=4） |
| ② 响度/增益被听成音调 | **独立通道，且只在 BlackHole 一路** | 同一段合成 PCM 分别过/不过守护进程的输出处理（配对复刻，8 句 / 249–286 帧对）：逐句 F0 中位 Δ=**0.000** 半音 ⇒ 输出链对音高贡献 0；而响度差异 100% 只在 BlackHole 路（monitor 路逐样本等于原始 PCM） |
| ③ 重采样/编解码伪影 | **合成侧不成立** | 合成输出原生 48 kHz、全链路无重采样；唯一重采样在参考音频（24 kHz→48 kHz）且每进程一次 |

**为什么「句间 F0 SD」不能用来判别**：以本机 7 个内置参考音色（自然人声录音，共 61.9 秒，按 ≥250 ms 静音切分为
**K=23 句 / 6 个音色**）建立自然基线，得**声内句间 F0 SD = 2.68 半音**（χ² 95% CI [2.01, 4.02]；
另用 HPS64 与自相关两种独立估计器复核为 2.41 / 1.89）。合成侧同口径只有 **1.54–1.85 半音**
（该区间是纳入规则依赖的：同一批已归档渲染按不同有效性规则复算得 1.38 / 1.54 / 1.85）。
**合成已经比自然人声更稳**，因此句间 SD 既不能判别抱怨，也不能当验收线；
并且「95% 上界 ≤2.0 半音」这条腿在任何样本量下都不可满足——K=16 时要求点估计 ≤1.39，
一个与真人同等稳的系统通过率仅 0.24%。

## 3. 根因链

### 3.1 采样侧：随机性从哪来

- `MOSS-TTS-Nano/ort_cpu_runtime.py` 的 `_normalize_sample_mode()` 与 `do_sample` 赋值使
  `do_sample = (sample_mode != "greedy")` ⇒ `moss_engine.py` 传入的 `do_sample=False` **完全失效**；
  `"fixed"` 的真实语义是「固定采样超参」，**不是确定性解码**。
- 采样算术在 `local_fixed_sampled_frame` **ONNX 图内**执行：独立二进制扫描该图名含
  `CumSum / Less / Where / TopK / Softmax / GatherElements`，**不含** `ArgMax / RandomUniform / Multinomial`
  ⇒ 图内无 RNG，uniform 由宿主喂入。采样超参（`audio_temperature=0.8`、`top_p=0.95`、`top_k=25`）
  是模型元数据里的**图内常量**——这解释了为何在 fixed 模式下改温度**逐字节相同**。
- 宿主 RNG 是进程级 `np.random.default_rng(1234)`（构造时播种一次），每 AR 帧消耗 `1 + n_vq = 17` 个 uniform，
  跨句**单调推进、永不复位**；而 KV / 重复历史 / prefill / 编解码状态**每句都重置**。
- `OnnxTtsRuntime.synthesize()` 有 `seed` 形参（非 None 时会重播种 RNG），但适配层从未传它。

### 3.2 结构侧：薄弱的跨句条件化与孤儿块

- `ttsd.py` 对每句调用一次 `engine.synth(s)`，每次 `synthesize()` 的唯一条件是同一参考 prompt，
  **没有跨句声学上下文**；句内还会按 ≤75 token 再切 chunk，每个 chunk 各自重新 prefill。
- 把相邻句打包到 ≤70 token 能减少单元数（6 段真实中文文本：28 → 11 个单元、拼接点 22 → 5），
  但实测只是**部分重定位**：单元内「同文本位置跨 seed」的 AR 漂移 σ=1.71 半音，占该位置方差 **48.1%**；
  4/4 个句内衔接点的台阶跨 seed 符号不一致。⇒ 打包**不是**音高修复。
- 真正的硬缺陷是**标点孤儿块**：文本按 token 预算二分切分时，若正文恰好吃满预算，句末「。」会被留成
  1 字 / 2 token 的独立 chunk。对该块做 21 次定点合成：**28.6%**（Wilson 13.8–50.0%）撞满 375 帧 = 30.00 秒，
  38.1% 超过 25.6 秒。机制已闭环——每个 chunk 消耗 `17×(帧数+1)` 个 uniform，在同一进程内推进到实测相位后
  单独合成可**逐帧复现**该结果，而相位差 17 个抽样即翻转结局（相位混沌）。
  超长尾巴的内容不是重复也不是噪声：30 秒内 65–90% 的 0.5 秒块低于 −60 dBFS、12–20% 采样精确为 0，
  另 18–37% 的块在 −16…−40 dB 形成 0.4–2 秒短爆发（本地 whisper 对 27.6 秒只转出 3 个字）。

### 3.3 增益侧：投递天花板与 G 无关

- `ttsd.py` 的增益与 0.95 FS 限幅**只作用于 BlackHole 标签**，且按 **0.2 秒子块**执行；monitor 路不做任何增益/限幅。
- 逐字复刻该链（增益 G=10.1）作用于既有合成：**65%** 的子块被限幅、块增益摆动 **9.63 dB**、
  块动态被压中位 **5.24 dB**。
- 三份独立 BlackHole 捕获的峰值**位级相同**为 0.115362965 FS（−18.759 dBFS，残差 0.00000 dB），
  该值等于 `0.95·a`，其中 `a = 10^(−64(1−s)/20) = 0.121437` 由设备音量标量 `s=0.71386` 经
  BlackHole v0.7.1 的 −64…0 dB 锥度换算（`BlackHole.c:282-283,477-482`；本机驱动为预编译包，
  该换算由「一个标量点 + 驱动源码常量」互证，未反汇编）。
- **推论**：限幅上限施加在设备音量之前 ⇒ 投递天花板 ≡ `0.95·a`，**与 G 无关**；加 G 必被限幅器吃掉。

### 3.4 部署侧：ρ 的两种含义

- **引擎空载**（生产同一段代码、threads=4、不传 seed、n=11）：fixed 的 ρ = Σ合成/Σ音频 = **0.784**，
  分层自助单侧 95% 上界 0.820，**未越 ρ=1**（测量时 1 分钟负载 2.83–9.95，CPU 限速 100%）。
- **上线之后**：守护进程自报的会话 ρ = **1.437 / 1.571**（由 `done` 事件给出的合成秒数与音频秒数算出）已越线。
  归因是**并发会话共享合成锁**导致的引擎串行化：N=2 时每会话吞吐 0.638 音频秒/墙钟秒 ⇒ 报告值 1.568，
  与实测 1.571/1.437 吻合到 ≤0.1%；生产日志记录到 171 秒的会话重叠，且崩溃转储显示一个线程阻塞在锁上、
  另一个正在解码。逐句/逐块代码开销被量级排除（13.8 秒句仅多 25.7 ms，占 0.2–0.3%）。
- **注意血统**：那两条 ρ>1 留档**早于本 skill 的全部提交**，且旧原型自身的干净基准也是 0.88–1.05
  ⇒「守护进程上下文比独立进程慢 1.6–1.8 倍」是两代共有现象，**不是本次重构的回归**。

## 5. 已被实测证伪的杠杆（勿再列入候选）

| 杠杆 | 出局理由（含量测口径） |
|---|---|
| 降低 `audio_temperature` | fixed 模式下温度是图内常量，改 T=0.8→0.5 输出**逐字节相同**；`full` 模式虽让温度真正可调（RTF 2.76 vs 1.92），但把 n 从 4 扩到 8 后效应消失（同一锚点句极差 4.87 vs 0.91 半音，方差比 p=0.027），且 **7.0%** 严重渲染失败（9/128 次：跑满 30 秒、近静音、时长离群），16 句朗读踩雷概率 **68.9%** |
| 改用 greedy 确定性解码 | 模型包内**不存在** `local_greedy_frame` 图，该分支不可达；已记录的 18 倍变慢也无可复现前提 |
| best-of-N 目标无关重排 | 8 seed 前瞻池 + 2000 次模拟：句间极差仅 3.96 → 3.16 半音（−20%），成本约 12.4 秒/句 |
| 参考音频长度 / 「音区偏置」 | 曾观察到「参考 F0 121.8 Hz、合成高 4.54–11.61 半音」，经查是**采样率标注伪影**：24 kHz 载荷按 16 kHz 刻度做基频估计，误差 `12·log2(24000/16000) = 7.02` 半音；按真实刻度三种独立估计器一致给出 179–186 Hz。受控对照（内置 Lingyu 218 帧 = 未截断原文件 vs 生产截断 54 帧，且 54 帧与其前 54 帧**逐量化位相同** 864/864）配对 n=8 中位 **−0.14 半音**（95% CI ±1.00）⇒ 参考长度非音区杠杆；同时条件化**确实锚定 F0**（跨 4 个参考，输出中位同步移动 6.24 半音，r=0.988） |
| 调整 `queue.Queue(maxsize=4)` | 队列是**整句 PCM** 粒度、消费端被设备时钟钉在 1.00 音频秒/墙钟秒，稳态深度仅 `1/ρ`（ρ=2.76 时 0.36 项）⇒ **永不饱和**；饱和阈值 ρ≤0.20 与已知可闻停顿阈值 ρ>1.01 相差 5 倍以上，调尺寸零收益 |

## 6. 验收判据

**结构门禁**（`scripts/selftest.py`，T1–T7）
- T1 只覆盖 `say` 兜底引擎，**不覆盖 MOSS 生产路径**（文档与 detail 已标明）。
- T3 语义是「输入通路/TCC 可用」：要求真实收到回调且无错误标记；电平**如实上报**（dBFS 进报告）但不做硬门禁——
  因为 T2 的测试音常在 T3 开流前已播完，正常情况也采到静音。
- **T6（新增）** MOSS 生产路径硬门禁：时长 <29.95 秒、RMS ≥−60 dBFS、**有声音频 ≥0.4 秒**。
  第三条刻意避开旧的「有声帧 <30」判据——它有长度偏置，会整批删掉短句的渲染。
- **T7（新增，零合成）** 切分层不变量：任何返回 chunk 去标点后必须非空（守护 §4 修复 2）。

**抖动门禁**（`scripts/tools/verify_render_stability.py`，需 K×n 次合成）
- 度量：**配对 σ_render** —— 同一句文本、同一说话人、只改 seed 重复渲染时 F0 中位的离散。
  仪器固定为 YIN 40 ms 帧 / 10 ms 跳 @16 kHz（与建立基线时同一仪器）。
- 规模与阈值：**K=16 句 × n=3 个独立 seed（df=32/臂）**，要求相对基线**降幅 ≥40%**
  （σ̂_fix ≤ 0.60×σ_base；基线 **1.08 半音**，df=24），单侧 F 检验 α=0.05 下达 80% 功效。
- 另设**非劣性守卫** σ̂_fix ≤ 1.50×σ_base：现存修复没有一条以降低解码抖动为目标，只设 40% 线会否掉全部候选。
- **绝对阈值不可用**：本机穷举 42 个自然语音文件（156.0 秒、43 段，含逐文件 ASR 文本比对与 MFCC 声学匹配）
  无「同说话人重复同句」样本。另注：30% 降幅在 df_base=24 下功效上限仅 75.1%，**不得把门槛写成 30%**。

**已知验证盲区**（该缺陷长期无记录的根因）：闭环 CER 转**无声调**拼音、参考侧又跑同一归一化 ⇒ 结构上发现不了声调问题；
旧 selftest 的 T1 走 macOS `say`、T3 在 −67.8 dBFS 仍判 PASS（本轮已修，见上）。

## 7. 如何自行复现关键结论

本报告不依赖外部产物；下面给出最小复现配方（都在本 skill 目录内可做）：

1. **F0 抖动**：用 `scripts/.venv-moss/bin/python` 直调 `MossEngine.synth(text)` 对同一文本重复合成，
   对每次输出做 YIN（40 ms/10 ms @16 kHz，60–400 Hz，帧 RMS 门限 0.02），取每帧中位的分布。
   判据看跨实现的 F0 中位极差（半音）。
2. **配对 σ_render**：`scripts/tools/verify_render_stability.py`（内置同仪器实现、F 检验与功耗提示）。
3. **标点孤儿块**：构造「恰好吃满 75 token 的无标点正文 + 。」，调上游 `split_voice_clone_text()`；
   修复后不应出现「去标点后为空」的 chunk（selftest T7 已固化该不变量）。
4. **增益链**：在既有合成 WAV 上按 `ttsd.py` 的 `feed()` 逻辑逐字复刻两版（逐块求峰 vs 每单元常量），
   比较块增益摆动与块动态。
5. **ρ**：以 `done` 事件的合成秒数 / 音频秒数得会话 ρ；空载对照需在无并发客户端时测。

## 8. 局限与未验证项

1. **跨句前缀已因未复现而回滚**：三次不配对自测给出互相矛盾的数（−32.5% / +24.2%），
   事前登记的配对测试（K=16 句 × 3 seed，两臂同句同 seed）在主判据上得到中位 −0.03 半音且**符号不一致**
   ⇒ 判为噪声，代码已回滚。保留的教训：**任何修复都用 §6 的配对设计与事前判定规则验收，不要用单次通过对比**。
2. **未直接验证**：切分层修复后「该单元永不撞满 375 帧」未验证（仅验证不再切出孤儿块；76 token ≈19.4 秒为推算）；
   常量增益上线后**设备侧**的最终响度与真实听感未做双路 A/B。
